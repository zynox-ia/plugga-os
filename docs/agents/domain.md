# Domain docs

Layout: **single-context**, com um `CONTEXT.md` e `docs/adr/` na raiz.

## Antes de explorar código

- Leia `CONTEXT.md`, se existir, para conhecer o vocabulário do domínio.
- Leia os ADRs de `docs/adr/` relevantes à tarefa.
- Se futuramente houver `CONTEXT-MAP.md`, siga os contextos relevantes indicados nele.
- Se esses arquivos não existirem, prossiga silenciosamente. A skill `domain-modeling` os cria conforme termos e decisões forem resolvidos.

## Vocabulário e decisões

Use os termos definidos em `CONTEXT.md` ao nomear conceitos em issues, propostas, hipóteses e testes. Leve dúvidas de negócio ao André.

Registre o glossário em `CONTEXT.md` e decisões arquiteturais relevantes em ADRs. Sinalize propostas que contradigam um ADR existente.

O Linear continua sendo a fonte dos critérios de aceite e das dependências.
